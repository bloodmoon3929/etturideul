# M0 브라우저 추론 검증 (PLAN 8.1)

상태: 워크스테이션에서 할 수 있는 부분까지 끝냄. 연구자 폰 측정이 남아 있어 진행/전환 판단은 아직 내리지 않았다.

## 1. 워크스테이션에서 확인한 것

### 모델 크기와 변환 정확도 (`scripts/export_onnx.py`, 상세는 `onnx_parity.md`)

| 인코더 | 변형 | 크기(MB) | PyTorch 대비 코사인 최소 / 평균 | 기준 | 판정 |
|---|---|---|---|---|---|
| 텍스트 | fp16 | 270.4 | 1.0000 / 1.0000 | 0.99 | 통과 |
| 텍스트 | q8 | 135.7 | 0.9934 / 0.9979 | 0.98 | 통과 |
| 이미지 | fp16 | 176.0 | 1.0000 / 1.0000 | 0.99 | 통과 |
| 이미지 | q8 | 96.2 | 0.9770 / 0.9900 (아래 전체 사진 결과 참고) | 0.98 | 미달 |

표본: 한국어·영어 문장 50개, 수집한 사진 50장. onnxruntime CPU에서 실행.

표본을 수집한 사진 421장 전체로 넓히면 이미지 q8은 최소 0.878, 하위 1% 0.960, 평균 0.988이고 0.98에 못 미치는 사진이 5.9%다. 이미지 fp16은 421장 모두 1.0000이다. 50장 표본의 최솟값(0.977)은 실제보다 좋게 나온 값이다.

| 조합 | 다운로드 합계(MB) | 250MB 기준 |
|---|---|---|
| q8 · WASM (둘 다 int8) | 231.9 | 통과 |
| 이미지 fp16 · WebGPU + 텍스트 q8 · WASM | 311.7 | 초과 |
| fp16 · WebGPU (둘 다 fp16) | 446.4 | 초과 |

- 250MB 기준을 넘지 않는 조합은 현재 q8뿐이다.
- fp16 조합은 텍스트 어휘 가지치기(PLAN 6.2)를 해도 250MB 아래로 내려가지 않는다. 이미지 인코더 176MB에 텍스트 인코더의 어휘 임베딩을 뺀 나머지(약 86MB)만 더해도 262MB이기 때문이다.
- 이미지 fp16 + 텍스트 q8 조합은 가지치기로 텍스트 인코더의 어휘를 3만 개 정도로 줄이면 약 245MB까지 내려갈 것으로 계산된다(가지치기는 아직 하지 않았고, 이 값은 추정이다).
- 이미지 q8의 정확도는 양자화 설정 13가지를 비교해 크기가 100MB 아래인 것 중 가장 좋은 값이다(처음 설정은 0.948). 0.98을 넘기려면 일부 층을 양자화에서 빼야 하고(약 139MB, 최소 0.983) 그러면 q8 합계가 약 274MB로 기준을 넘는다.
- 런타임 파일(onnxruntime WASM 약 27MB)은 위 합계와 별도다.

### 브라우저 실행 (이 워크스테이션의 헤드리스 Chrome 153, q8 · WASM)

폰이 아니므로 속도는 참고값이다. 여기서 확인한 것은 "브라우저에서 끝까지 돈다"와 "브라우저 전처리·토크나이저가 파이썬과 같은 결과를 낸다"이다.

| 항목 | 결과 |
|---|---|
| 모델 로드 → 텍스트 10건, 사진 10장 임베딩 | 오류 없이 완료 |
| 브라우저 출력 vs PyTorch 코사인 (텍스트 10건) | 최소 0.9969 |
| 브라우저 출력 vs PyTorch 코사인 (사진 10장, 전처리 포함) | 최소 0.9804, 평균 0.9919 |
| 텍스트 1건 / 사진 1건 (데스크톱 CPU 64코어) | 17ms / 124ms (전처리 37ms 포함) |
| WebGPU를 못 쓰는 환경에서 fp16 조합을 고름 | q8 · WASM으로 자동 전환됨 |
| 오프라인 | 한 번 준비한 뒤 네트워크를 끊고 새로고침해도 모델 로드와 검색이 됨 |

확인하지 못한 것: WebGPU 경로(이 워크스테이션의 헤드리스 Chrome은 소프트웨어 GPU라 fp16 셰이더를 지원하지 않음), 폰에서의 속도·메모리·안정성.

## 3. 폰에 띄우는 방법

WebGPU와 서비스 워커는 HTTPS 또는 localhost에서만 동작한다. 이 워크스테이션에는 adb가 없고 Firebase Hosting도 쓸 수 없어 아래 중 하나가 필요하다.

1. adb 설치 후 USB 연결: `python scripts/dev_server.py` 실행 → `adb reverse tcp:8000 tcp:8000` → 폰 Chrome에서 `http://localhost:8000/m0/`
2. HTTPS 정적 호스팅에 `web/`과 `models/`를 올림(예: Hugging Face Static Space). 교차 출처 격리 헤더(COOP/COEP)를 줄 수 있어야 WASM 멀티스레드가 켜진다.

## 4. 판단에 필요한 결정

- 250MB 기준을 지킬지: 지키면 q8 · WASM이 기본이 되고, 이미지 q8이 정확도 기준에 못 미치는 점(사진의 5.9%가 0.98 미만, 최소 0.878)을 받아들여야 한다. 실제 검색 품질 영향은 M4의 Recall@5 비교(PyTorch vs 브라우저 모델)로 확인한다.
- WebGPU로 사진 검색 속도를 얻을지: 그러면 이미지 fp16 + 텍스트 q8 조합에 어휘 가지치기가 필요하다.
